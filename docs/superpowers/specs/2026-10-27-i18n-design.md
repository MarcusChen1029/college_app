# Translated UI: Traditional Chinese (zh-TW) — design and status

Roadmap item #12. Date: 2026-10-27. The owner said "don't ask, just choose"; every decision below was made on that basis and can be revisited.

## Goal

Students (many from Taiwan) can use the app in Traditional Chinese. English stays the default. UI chrome is translated; data is not.

## Mechanism (and why)

- **No locale in the URL.** Next's own i18n guide puts every route under `app/[lang]` with a proxy redirect. That restructures every
  route and file, so it was rejected (task constraint). Instead the language lives in a **cookie** named `lang` (`en` | `zh-TW`, one year,
  `SameSite=Lax`, path `/`). No localStorage copy: the server needs the value, and one store can't disagree with itself.
- **Reading it under `cacheComponents`.** `cookies()` is request data, and outside a `<Suspense>` it fails the prerender
  (blocking-prerender-runtime). So `app/layout.tsx` renders `<Suspense fallback={<ShellFallback/>}><LocaleRoot>…</LocaleRoot></Suspense>`.
  `LocaleRoot` (async server component) reads the cookie once, wraps the header, main and footer in `<I18nProvider locale>` and
  renders the page. Every route still builds as Partial Prerender (◐). The static shell is now a bare header (logo only), and the rest
  streams in already in the visitor's language. The `"use cache"` functions in `lib/data.ts` are untouched: they never read the locale.
  Cost: the page body is no longer in the static shell. That is acceptable because almost every page was already a client component
  reading localStorage, and the data reads stay cached.
- **No hydration mismatches.** The server passes the locale to `I18nProvider` (a client context), so the server HTML and the first client
  render use the same dictionary. Server components call `await getT()` (`lib/i18n/server.ts`). That works because every page is below
  the layout's Suspense boundary. It must never be called inside a `"use cache"` function.
- **`<html lang>`.** The root layout is outside the boundary, so it prerenders `lang="en"`. `LocaleRoot` emits a one-line inline script
  (`document.documentElement.lang="zh-Hant-TW"`) that runs while the HTML parses. `<html suppressHydrationWarning>` covers it (the pattern
  from Next's "preventing flash before hydration" guide), and `I18nProvider` also sets it in an effect.
- **Switching.** `setLocale()` writes the cookie and does a full `location.reload()`. A rare action does not need `router.refresh()`, and a
  reload guarantees that server text, client text and every cached router payload switch together. Controls: a small "中文 / EN" button
  at the right end of the header (`components/LanguageSwitch.tsx`) and a "Language" card at the top of `/settings` (English | 繁體中文).
- **No auto-detection** from `Accept-Language`: the task says English stays default, and a predictable default beats a guess. Easy to add
  later in `getLocale()`.
- **Signed-in sync:** none. The choice is per browser, because the task allows no DB changes.
- **Metadata titles** (`<title>`) stay English. Translating them means `generateMetadata` reading cookies, which is runtime data in metadata
  and needs extra Suspense wiring for little gain.

## Files

- `web/lib/i18n/core.ts`: `Locale`, `parseLocale`, cookie name, `HTML_LANG`, `interpolate` (`{var}`; unknown vars stay visible).
- `web/lib/i18n/messages/<section>.ts`: one file per area, each exporting `en = {...} as const` and
  `zhTW: Translation<typeof en>`. A missing or extra key in a section fails `tsc`. Keys are prefixed by section (`settings.title`).
- `web/lib/i18n/sections.ts` lists the sections. `en.ts` / `zh-TW.ts` spread them into the two dictionaries. `zh-TW.ts` is typed `Messages`
  (derived from `en`), so a missing key fails `tsc` there too.
- `web/lib/i18n/index.ts`: `translate`, `makeT`, `TFunction`, `MessageKey`, `navLabel` (maps the English labels kept in `lib/roles.ts`
  and the tab lists to keys, so `roles.test.ts` still asserts English).
- `web/lib/i18n/client.tsx`: `I18nProvider`, `useLocale`, `useT`, `setLocale`. `web/lib/i18n/server.ts`: `getLocale`, `getT`.
- `web/lib/i18n/fit-text.ts`: words `computeFit` results. `lib/fit.ts` now also returns structured `parts`; `reason` is unchanged, and
  a test checks that the English text equals `reason`.
- Libraries that return English and have tests (`lib/status.ts`, `join-codes.ts`, `roles.ts`, `roster.ts`, `share-links.ts`, …) are unchanged.
  Components translate at the edge by id or enum value, falling back to the English string. Teacher pages share these helpers in `components/TeacherText.ts`.
- Tests: `web/lib/i18n.test.ts` checks:
  - Both dictionaries have the same keys, none empty, with the same `{placeholders}`.
  - No key is defined by two sections, and each section's keys carry its prefix.
  - Interpolation works, and `parseLocale` falls back to English.
  - Every nav label has a translation.
  - The English fit reason equals `lib/fit.ts`.
  - **No unused keys**: a source scan for the literal key, or for a `` `prefix.${…}` `` / `"prefix." +` dynamic key.

## Rules for adding text

1. Put the English string in the right `messages/<section>.ts` (`en`) and its Chinese in `zhTW`. `tsc` fails until both exist.
2. Client component: `const t = useT()` (before any early return). Server component: `const t = await getT()`.
3. Never translate stored values, values matched by portals/extension/AI, exported CSV, the résumé document or Google Doc titles.

## Remaining (English in zh-TW, by decision or not reached)

- **Not reached:** `/oauth/consent` (OAuthConsent.tsx) and `/extension/connect` (ExtensionConnect.tsx). Both are short flow pages.
- **Deliberately English:**
  - `<title>` metadata.
  - The résumé document and Google Doc titles, which go to US colleges.
  - Roster CSV export.
  - The AI context pack, MCP tool output and the transcript AI copy-prompt / JSON format.
  - Transcript dropdown values and portal wording from `lib/transcript*` (they must match the portals).
  - Validation messages generated inside `lib/transcript*.ts` and `lib/custom-college.ts`.
  - Program (CIP) names in quiz results.
  - Plan names (Free/Junior/Senior).
  - Claude/ChatGPT menu names inside the Connect AI steps.
- **Data-ish label maps in `lib/format.ts`** (`TEST_POLICY`, `ENGLISH_POLICY`, `INTL_AID`, `PLATFORM`, `INTERVIEW`, `ADMIT_MODEL`, …):
  translated by value in the `/colleges` explorer, but still English on `/colleges/[slug]` and `/compare`. Next step: move the explorer's
  `colleges.testPolicy.*` / `englishPolicy.*` / `intlAid.*` mapping into a shared helper and use it on those two pages.
- **Database labels** (deadline names such as "Early Decision I", application plan names, category labels) are data and stay English.
- **Dates** use the existing `fmtDate` (English month names) everywhere except the teacher deadlines and task dates, which use zh-TW formatting.

Style rules:
- Address the student as 你 (not 您).
- Use full-width punctuation in Chinese sentences.
- Put a half-width space between Chinese and Latin letters or digits (`剩 3 天`, `SAT 成績`).
- Keep these in English: Common App, SAT, ACT, TOEFL, IELTS, Duolingo, PTE, Cambridge, UCAS, CDS, AP, IB, GPA, FAFSA, CSS Profile, ED/EA/REA/RD, Google, AI, MCP.

## Verification (2026-10-27)

- `rm -rf .next && next build`, `tsc --noEmit`, `eslint` and `node --test lib/*.test.ts` all exit 0 (436 tests).
- Dev server on port 3104: `/` and `/settings` with `Cookie: lang=zh-TW` contain Chinese ("整理你的", "學校清單", "設定", "語言", "主要導覽")
  and no English hero or footer text. Without the cookie they are English.
- In the app's browser pane: `<html lang>` became `zh-Hant-TW`, there were no hydration or console errors, and clicking "English" on
  `/settings` set `lang=en` and reloaded in English.
  - Caveat: in a hidden pane, React's streamed-boundary reveal waits for `requestAnimationFrame`, so the reveal was triggered by hand
    there. Normal visible tabs reveal immediately.
- Not checked: every translated page by eye in Chinese, and the signed-in and teacher screens.
- Translations were written by parallel agents against one shared glossary and have not been reviewed by a native speaker.

# Security audit and hardening, 2026-10-28

Two review rounds over the whole system (web app, Supabase database, MCP/Connect AI, Chrome extension, edge function,
secrets/git history, dependencies), each by fresh reviewers who had not written the code; fixes on branch
`fix/security-hardening`. No leaked secrets were found in git history; `npm audit` is clean for web and extension.

## What was wrong, and what changed

| Area | Problem | Fix |
|---|---|---|
| Portal passwords | Stored as plain text in `student_colleges.portal_password` and `student_profiles.portals`, readable by a leaked service key, a DB dump, dashboard users, and any approved AI connection; kept in plain text in localStorage when signed out | New `portal_passwords` table, service-role only, AES-256-GCM sealed per user and slot (`web/lib/portal-vault.ts`). Shown only on demand through `POST /api/portal-passwords`, which refuses AI tokens. Existing passwords move on each student's next visit, and plain text is removed only after the sealed copy is read back and opened. 0043 removes the old column from client access and refuses any new plain text. Nothing is stored in the browser any more. **Update 2026-10-29:** passwords are now locked in the student's browser with a vault passphrase (`docs/superpowers/specs/2026-10-29-e2e-portal-vault-design.md`), so this server key no longer opens new ones; old rows move into the vault on the student's next unlock |
| Connect AI (MCP OAuth) | An approved AI app's token was a full session: it could read and change everything, mint extension tokens and share links, join classes, switch roles, and read saved-login usernames and links | Pre-request hook `api_request_guard` lets AI tokens reach only the transcript tables and two column-limited views, `ai_student_profiles` / `ai_student_colleges`, which hold just the columns the tools use (no saved logins, reminder settings or essays; 0043 then takes the base profile/list tables away from AI tokens); restrictive policies on 20 tables; 33 RPCs refuse them; trigger blocks AI writes to plan/reminder emails/logins and AI deletes. Consent page refuses non-https return addresses, shows the real return host and warns about unknown apps |
| Browser | No security headers | CSP (only this site and Supabase can be contacted; no framing, plugins or base-tag tricks), X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy; share links get no-referrer, noindex and no-store |
| Database | Unbounded writes could fill the free 500 MB DB; race-able join-code limit; biased codes; share links never expired; essays shared by default; new functions auto-exposed | Size and row caps, cleanup of revoked tokens and links, advisory locks, unbiased codes, 180-day share links, essays opt-in, no default EXECUTE on new functions |
| Extension | Sign-out didn't revoke the 90-day token; token readable by content scripts; no sender check; extra permissions; save buttons pressed by id only | Token revoked on sign-out, storage locked to the extension, side-panel-only messages, `tabs` and Supabase host permissions dropped, label-guarded save buttons, URL guard, no localhost in release builds, trimmed transcript RPC |
| Other | Google Docs routes accepted AI tokens; no account deletion; unvalidated slugs could hammer the DB; phishing text in teacher emails; edge function trusted a caller's date; insecure setup docs | All fixed: website-only tokens, Settings > Delete account, slug checks, flattened email text, clamped date, corrected DEPLOY/LOCAL docs, wider `.gitignore` |

## What the owner must do outside the code

1. **Supabase → Authentication → URL Configuration:** the redirect list must contain only `https://www.track-ur-college.com/**`
   (and `http://localhost:3000/**` if needed). Remove any `*.vercel.app` wildcard: anyone can create a matching Vercel
   project and take over accounts.
2. **Supabase → Authentication:** keep Email, Phone and Anonymous sign-in **off** (verified off on 2026-10-28) and keep
   **manual identity linking off**. Otherwise an AI connection could turn itself into a normal login.
3. **GitHub:** consider making `MarcusChen1029/college_app` private. It's public today, so the schema, policies and
   function bodies of an app holding minors' data are open to everyone.
4. **Supabase MCP in research sessions:** don't connect it in sessions that read web pages. A planted instruction in a
   page could ask the agent to run SQL.
5. **Extension distribution:** publish through the Chrome Web Store for signed auto-updates (the zip download can't
   update itself, and anyone can build an extension with the same id).

## What can never be fully removed

A browser web app that shows a secret to its owner can leak it to script running on its own origin. If an XSS bug
ever appeared (or the site's code were changed), it could use the unlocked password vault in that tab or capture what the
student types. The CSP narrows where data can be sent, React escapes all text, and no unsafe HTML sink exists today. Since
2026-10-29 the server and its keys are no longer a root of trust for passwords (they hold only browser-locked values), so the
site's own code in the browser is the remaining one. Approved AI apps can still read and change the
student's tracker data the tools use (scores, activities, résumé settings, list, checklist, notes, transcript), which
is the feature itself, but not saved logins (after 0043). The unknown-app warning is the defence there.
